# Why Are We Here?

## My Starting Point

As a student with a background in design, I used to see programming mainly as a way to turn my design ideas into experiences that could actually work in practice. But as AI becomes increasingly capable of generating functional code directly from natural language, that reason no longer feels as convincing as it once did. If I may no longer need to write every line of code myself in the future, why do I still need to understand programming?

## When I Knew What I Wanted, But Could Not Build It

During my undergraduate studies, I worked on interaction design projects for people who are often overlooked in mainstream digital innovation, including older adults, people with visual impairments, and families who had lost their only child. These experiences gradually made me realise that design should not only serve mainstream users, but should also pay attention to those who can easily be left behind as technology develops. Inclusive design therefore became an important part of my design practice.

For my graduation project, I designed a music-based motion game for people with visual impairments. Through music, body movement, and multisensory feedback, I wanted to create a more accessible and enjoyable way for them to experience space and interact through play. Rather than simply compensating for visual impairment, I wanted to explore a more inclusive experience in which visually impaired and sighted users could take part in the same musical interaction, playing, communicating, and expressing themselves together in a shared environment.

I used Arduino and TouchDesigner to build a full-scale, functional music mat prototype. Stepping on different keys on the mat would trigger different piano notes, while actions such as clapping or tapping different parts of the body would produce different instrumental sounds. I also used TouchDesigner to connect these movements with dynamic visuals, so that a single action could produce both sound and visual feedback. As users continued to interact, these visual elements would gradually come together to form a complete graphic score, encouraging more sighted users to join the experience.

I actually had a very clear idea of the experience I wanted to create, but I did not know how to translate that idea precisely into a computational system. Because I was unfamiliar with programming and the logic behind these systems, I found it difficult to turn my design intentions into a stable interaction that worked as I imagined. For example, I needed to work out exactly when different sounds should be triggered, how sensitive the motion detection should be, and how sound and visual feedback should respond to each other. All of these interaction rules had to be translated into instructions that a computer could actually execute. At the time, I could describe the experience I wanted, but I lacked the ability to turn that intention into specific computational logic.

## What Changes When AI Can Write the Code?

If I developed the same project today, AI could probably generate much of the code that I struggled with at the time. I could simply describe an interaction — for example, asking the system to trigger a sound and a visual animation when a user claps — and AI might be able to produce a solution that technically works. This makes my old reason for learning programming — simply being able to write the code myself — less convincing to me.

This question is not entirely new. In her notes on Charles Babbage's Analytical Engine, Ada Lovelace argued that the machine could perform what humans knew how to instruct it to perform, rather than originate intentions of its own. Although today's AI is very different from the Analytical Engine, this distinction still makes me think about where intention sits in my own design process.

More than a century later, Alan Turing approached the relationship between humans and machines from another direction. In *Computing Machinery and Intelligence*, he moved away from the abstract question “Can machines think?” and introduced the imitation game, shifting attention towards what a machine can actually demonstrate through its behaviour. In 2026, when AI can already generate code from ordinary language, this history makes the question feel much more immediate to me: if a machine can produce the result I ask for, what do I still need to understand as the designer?

Of course, working code does not necessarily mean a successful interaction. Even if AI could now help me program this game, making an action successfully trigger sound and visual feedback would still only be the first step. I would still need to judge whether the sound felt right, whether the timing of the response was appropriate, how the visuals should change, and whether these different forms of feedback came together to create the sensory experience I intended. Especially when my goal was to create an experience in which visually impaired and sighted users could participate together, these decisions would still depend on my own design intentions and judgement.

This is why, for me, AI changes my reason for learning programming rather than removing it. I may not need to write every line of code myself in the future, but I still need enough understanding of programming to specify what I want, read what AI has generated, understand why it works the way it does, and modify it when the result does not match my intention. I can hand over some of the coding to AI, but I should not hand over my judgement with it.

## Code as a Creative Medium

Dylan Beattie's *The Art of Code* also changed the way I think about programming. The examples he presented made me realise that code can be more than a practical tool for making software work; it can also become a creative and expressive medium. As someone with a background in design, I find this idea particularly meaningful.

In design, understanding a material is not simply about knowing how to use it to make something. Its properties and limitations also shape what a designer is able to imagine and create. I am beginning to think about programming in a similar way. If computation is becoming one of the “materials” I design with, relying entirely on AI to work with that material would leave part of my own design process inaccessible to me.

Don Ihde's discussion of human–technology relations gives me another way to think about this. Rather than seeing technologies simply as neutral tools, Ihde focuses on how they mediate and shape the relationship between people and the world. For me, this suggests that learning programming is also a way of understanding computational media: how they shape what I can perceive, create, and imagine as a designer.

Of course, this does not mean that I need to reject AI, or that I have to write every line of code from scratch myself. I would rather use AI as a tool to help me work with code more efficiently and bring my ideas to life. But learning programming allows me to understand code itself and use it as a creative medium, rather than simply accepting the results AI gives me. This understanding can help me discover new possibilities, recognise limitations, and make more active and deliberate creative decisions instead of accepting a result simply because the system has produced it.

## Why I Am Here

I do not know how much code I will still need to write myself in the future. As AI continues to develop, perhaps I will need to write less and less of it myself. But this does not make learning programming meaningless to me. Instead, it changes what I want to learn from it.

I am not learning programming to compete with AI over who can write code faster, nor do I believe that everything has to be done by myself. What matters more to me is being able to understand how my design intentions are translated into computational logic, judge whether something that technically works actually creates the experience I want, and explore possibilities beyond the answers AI gives me. AI can help me reach a result more quickly, but what kind of experience I want to create, which results I choose to accept or change, and why I make those choices are still decisions I need to make for myself.

The way we write code may change dramatically in the future, but I do not want increasingly powerful tools to gradually take away my ability to understand, judge, choose, and create. For me, that is why learning programming still matters.
